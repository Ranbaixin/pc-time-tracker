# PC Time Tracker 后续修改建议

本文记录本轮轻量实现后暂缓的工作，避免继续扩大当前改动范围。

## 本轮已经完成

- 新增非破坏性的活动区间归一化，统计时消除休眠、空闲和历史活动重叠。
- 跨天、跨小时及当前开放活动按真实查询区间计算，不再依赖错误时长截断。
- 桌面活动作为总时长权威来源，浏览器记录仅丰富站点和内容维度。
- 同进程标题变化会生成新活动并重新分类。
- 空闲和休眠使用独立的 `system` 来源记录，休眠不会再重复计入活动时间。
- SQLite 使用一致性在线备份，并加入版本化迁移和迁移前备份。
- stats、Agent、Session 和 CLI 使用统一统计口径。
- 配置原子保存、基础热更新、日志轮转、8088 端口和 MCP 依赖已统一。
- 自启动改为共享的动态 VBS 启动器，不再依赖仓库中的本机硬编码脚本。
- 已建立 pytest、覆盖率和 Ruff 检查基础。

## 建议下一轮优先处理

### 1. 真实机器采集验收

- 在实际 Windows 休眠、锁屏、唤醒场景下连续运行 2～3 天。
- 验证每个 session 最多只有一条开放 desktop/system 活动。
- 对比 Windows 登录/休眠事件，确认轮询推断的边界误差在一个 poll interval 内。
- 验证注册表自启动在重启后确实启动 8088 服务。

### 2. 历史数据诊断工具

- 增加只读 `doctor` CLI，报告非法时间戳、负时长、重叠区间和开放陈旧记录。
- 默认只生成报告，不删除或修改原始历史活动。
- 如需物理修复，应先生成 SQLite 一致性备份和修复预览。

### 3. 浏览器扩展协议

- 为扩展事件增加稳定 `event_id`，服务端建立唯一索引以支持幂等重试。
- 明确批次确认、离线缓存、时钟偏差和扩展版本字段。
- 将扩展源码纳入仓库后，再补端到端浏览器覆盖测试。

### 4. 测试与 CI

- 为 TrackerEngine 完整线程生命周期和异常恢复补集成测试。
- 为 Win32 API 适配层增加 Windows 专用测试。
- 在 GitHub Actions 或其他 CI 上运行 pytest、coverage 和 Ruff。
- 将整体覆盖率门槛固定为 80%，新增核心模块保持 90% 以上。

### 5. 仓库和发布整理

- `data/config.json` 当前仍是已跟踪文件；确认团队工作流后执行
  `git rm --cached data/config.json`，保留本地配置但停止提交个人设置。
- 增加锁定依赖或可复现环境文件。
- 后续可制作 PyInstaller 便携包；本轮继续使用 `python -m src.main`。
- 增加版本号、变更日志、升级与回滚说明。

## 中长期优化

- 拆分较大的 `tracker.py`、`agent.py` 和仪表盘单文件。
- 为隐私模式、应用/标题排除规则、数据保留期限和导出增加产品设计。
- 评估启用 `resource_samples` 及 CPU、内存、电池采集的实际价值。
- 将 Chart.js 固定到本地资源或增加 SRI，减少外部 CDN 依赖。
- 在桌面数据稳定后，再考虑跨平台采集、加密同步和插件 SDK。
